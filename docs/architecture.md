## 三通道输入模型

系统不只等用户开口。信息从三条通道同时进入：

```
        ┌──────────────┐
        │ 数据自动监控  │ ← 不间断，秒级（主要通道）
        │ Autoencoder   │   异常标红自动触发，不依赖人
        └──────┬───────┘
               │
        ┌──────┴───────┐
        │ 外部系统对接  │ ← 持续性，提供上下文
        │ 雷达/气象/    │   汇总分散系统的数据
        │ 军航/飞行计划 │
        └──────┬───────┘
               │
        ┌──────┴───────┐
        │ 管制员主动提问 │ ← 按需，自然语言（交互通道）
        │ "受影响多少班" │   追问细节
        └──────┬───────┘
               │
               ▼
        ┌──────────────┐
        │  空管智能助手 │
        │  评估→建议→通知│
        └──────────────┘
```

**V1（当前）**: Chatbot 模式，用户提问 → Agent 查数据 → 回答。5 工具覆盖数据查询和 DL 推理。

**V2（规划）**: 从 Chatbot 升级为业务闭环系统。Autoencoder 持续监控 → 异常触发 → Agent 评估影响 → 推荐处置措施 → 生成通知 → 事后复盘。用户可以是管制员主动提问，也可以是系统自动触发。

## Agent ↔ LLM 循环

```
用户提问 / 自动触发 → Agent → LLM（判断需要什么工具）
                                ↓ 返回 tool_call
                            Agent 执行工具 → 结果塞回对话
                                ↓
                            LLM（还需要更多信息？）
                                ↓ 否
                            输出评估/建议/通知
```

## 技术选型理由

| 选择 | 理由 |
|------|------|
| 通义千问 | 空管涉及敏感数据，国产模型满足合规要求；DashScope 兼容 OpenAI 协议；成本约为 GPT-4o 的 1/40 |
| LangChain | JD 明确要求，生态最完善 |
| Chroma | 轻量级、本地部署、与 LangChain 原生集成 |
| LangGraph | LangChain 官方 Agent 框架，ReAct 模式成熟 |
| Chainlit | 为 LLM 应用设计的现代对话界面，Agent 工具调用可视化 |
| FastAPI | 异步高性能，LangServe 原生支持 |

## 数据流

### 航班查询
```
flights.csv (10K 行) → Pandas 过滤 → 统计摘要 → Agent → 用户
```

### 法规问答
```
法规文档 (.md) → TextSplitter → Embedding → Chroma
                                               ↓
用户提问 → Agent → search_regulations → 相似度检索(k=5) → LLM生成 → 回答
```

### 流量分析
```
flow_history.csv (43K 行) → Pandas tail(24h) → 指标表 → Agent → 用户
```

### DL 推理
```
flow_history.csv → 滑动窗口 → LSTM → 预测值
                            → Autoencoder → z-score → 正常/异常
```

## 空地协同架构

地面端智能助手解决"管制员怎么决策"。但飞机上发生的事，管制员不一定第一时间知道。机载子系统是地面端输入通道的延伸——**从驾驶舱直达决策引擎**。

```
                         卫星数据链 / ACARS
        ┌─────────────────────┬─────────────────────┐
        │                     │                     │
        ▼                     ▼                     ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  机载子系统   │     │  机载子系统   │     │  机载子系统   │
│  (轻量版)     │     │  (轻量版)     │     │  (轻量版)     │
│              │     │              │     │              │
│ 本地小模型 +  │     │ 本地小模型 +  │     │ 本地小模型 +  │
│ 规则引擎      │     │ 规则引擎      │     │ 规则引擎      │
│              │     │              │     │              │
│ • 状态监测    │     │              │     │              │
│ • 故障自动打包 │     │              │     │              │
│ • 接收地面方案 │     │              │     │              │
└──────┬───────┘     └──────┬───────┘     └──────┬───────┘
       │                    │                    │
       └────────────────────┼────────────────────┘
                            │ 结构化数据包（JSON）
                            ▼
              ┌─────────────────────────┐
              │    空管智能助手（地面端） │
              │   评估引擎 → 备降方案排序 │
              │   → 空域调整 → 通知清单   │
              └─────────────────────────┘
```

机载端只做三件事：监测故障、打包上下文发给地面、显示地面推荐的方案让机组确认。复杂推理全部在地面端完成。机载端不依赖云端 LLM，用本地量化模型 + 规则引擎。链路中断时仍有离线版故障检查单。
